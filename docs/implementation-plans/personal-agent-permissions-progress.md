## 2. P1 已实现内容

1. 配置默认关闭；开启时核对固定所有者、管理身份、所有者沙箱、禁止 legacy fallback 和所有者维护入口。
2. Task payload 增加 `identityMode`、`agentOwnerUserId`；不批量改写旧任务，不升级数据库 schema。
3. 集中身份解析区分执行所有者、真实请求者和实际受众。旧任务不因总开关开启而转换；已标记的新模式任务关闭开关后拒绝解析，不回退请求者身份。
4. 群身份解析要求提供合法版本号，但不证明版本当前有效；当前成员资格、服务是否启用与真实版本校验仍由 P2/P8 接入。身份解析结果不是准入结论。
5. SQLite 和文件存储阻止改写/删除既有任务身份或原地转换模式，覆盖原地修改 updater 对象的情况；SQLite 校验与 upsert 在同一事务内。直接 SQL 的 legacy fallback 也拒绝新模式任务。
6. 示例只增加关闭状态。入口路由、任务创建、沙箱调用和 CLI 账号调用尚未接入新模式，仍属于后续工作包。

未复制其他用户凭据，未重启服务、修改生产配置或运行生产数据库迁移。开工时已有的 Git 错误分类修改保持原样，不归入本阶段。

## 5. P2/P3 的离线实现与 P4 的局部防护

### 已落地的代码

1. 增量 schema 34 增加群服务事实与事件去重表；版本随有效状态变化增加，撤销墓碑保留。迁移只在临时数据库测试，未运行生产迁移。
2. 同一事务完成事件去重、时间排序、版本 CAS 和状态写入；重复事件不重复增版，旧邀请不能覆盖新撤销，同时间移除优先。异步成员校验期间发生撤销时，过期校验不能启用群服务。
3. 未识别邀请人或群资格查询失败只能进入 pending；所有者邀请还需新鲜的所有者成员资格及机器人在群验证。验证依赖已定义并测试，真实平台适配尚未接线。
4. 所有者私聊管理命令解析器支持 enable/disable，要求平台消息 ID，重复消息幂等。命令与生命周期回调均未挂到生产入口，全局用户白名单未改变。
5. 可选的新模式 ConversationTaskService 使用 agent-topic/agent-group；所有者私聊使用独立 agent-private 命名空间，避免把旧任务原地升级。保留 purpose 隔离，拒绝旧 scope 兼容回退。
6. 共享任务固定属于所有者，A/B 分别记录为 member；仅所有者可执行删除、成员管理和长期记忆管理。持久化 administrator 角色也不能替代固定所有者。一般项目资格仍待 P5 接入，不把成员操作权限当作资源授权。
7. 并发任务创建采用 scope 锁与 SQLite immediate 事务；插入前在同一事务重验群版本。创建结果返回实际是否新建，不以预先查询结果声称创建成功。
8. 沙箱恢复从持久化任务取执行所有者；拒绝传入不匹配的 owner。新模式失败时禁止进入 legacy fallback，且直接 fallback 在回收容器之前拒绝，避免伤及其他任务。附件与认证刷新继续使用已持久化所有者，并有新增回归测试。

- 所有者已指定受控群，并选择先完成新链路、仅开放该群，不接受旧模式临时放行。已确认原请求在 ingress 用户白名单处被拒绝；全局放行开关仍关闭。

- 真实任务 UID 下使用 CLI user 身份成功创建了一份空白测试文档；没有请求群成员授权，没有修改既有文档。新增文档不代表完整交付成功。

## 7. 以非管理员创建文档请求为主线补齐

### 本轮新增代码与验证

1. 主验收目标明确为“非管理员发起请求，代理使用所有者身份创建文档并返回”，不是让非管理员授权自己的账号，也不是仅验证打开一份手工创建的文档。前述空白文档只作为 CLI 能力原型，不能算主链路通过。
2. 补出 TaskPlatformService 集成用例：普通群无 topic ID 的文档请求启动项目无关任务，不误走仓库选择；A 发起、B 补充共用任务和所有者沙箱，真实作者与跟进作者分别保留。该用例使用假后端，不伪称真实文档已由群请求创建。
3. 新增准入模块及 Gateway/应用入口接线：资格来自服务端群记录与新鲜成员查询，成员查询失败、版本变化、其他群、陌生人私聊均不放行。不改 allowedUsers，不启用全局未列用户放行；暂只开放普通文本任务，非所有者管理命令及卡片操作仍拒绝，完整成员交互尚未完成。
4. 群显式启用验证机器人当前在群且固定所有者为成员；可信生命周期回调交由群服务处理。真实邀请/移除事件订阅与实际撤销链路仍需测试，不把 SDK 类型与假事件当作事实。
5. 主轮次与跟进提示包含分离的所有者、请求者、受众事实；群轮次持久化原资格版本。新模式普通请求不进入请求者授权 broker，不把真实 actor 改成管理员。
6. 原生审批归属固定所有者，持久化来源受众、请求者、群版本和操作快照摘要；未能证明仅为澄清的原生 user_input 也不让成员批准。发送目标改为所有者私聊，回调要求原始私聊卡片；群回调、请求者和转发卡不能批准，处理前重验原来源和快照。
7. 新模式隐藏内容不进入私聊补发路径；凭据脱敏继续保留。业务链接与全部流式/详情出口的精细化边界尚未全部改完。
8. 待投递结果加撤销检查，失效任务结果停止重试但不标为已发送，重新启用也不重新投递。缺少可靠轮次来源的新模式投递采用拒绝，而不是替换成最新版本。
9. CLI wrapper 增加实际账号核验，要求相同应用与固定用户 ID，不比较昵称；业务命令要求 user 身份，不降级 bot，不允许业务链路修改登录配置。原生 auth status 不接受 --as，镜像实测发现后已修正诊断分支并补回归。
10. 身份配置只读挂载到所有者容器，已运行但没有该挂载的容器拒绝新模式执行并要求受控升级，不自动回收共享容器。保留旧镜像和持久卷。该 wrapper 不是任意 shell/原生二进制绕过的完整安全边界；原生工具与直发路径清单仍需完成。

## 8. 生命周期真实验收预检

所有者已明确允许仅在测试群移除并重新邀请机器人一次。CLI 只读核对确认目标群包含固定所有者、两位非所有者成员和目标机器人；所有者 user 身份有效且具备群成员写入 scope。移除与重新邀请参数已分别 dry-run，只指定目标机器人的 app ID，不操作用户成员。

实际移除尚未执行。预检核对已安装 SDK 文档：同一应用多个长连接是集群随机分发，不是广播；不能临时起第二个消费者抢走现网消息。已部署 dist 尚无生命周期处理器，当前直接操作无法验证真实事件接收和服务资格变化。

### 本轮补齐

- 新增持久化工作围栏：轮次开始、steer、自动重试、断线接续、启动恢复、受控工具请求及直接回复投递核对原群版本。恢复请求者还需重新核验当前群成员资格；不以所有者身份冒充请求者通过成员校验。

- 命令确认的一次性票据绑定全部操作参数，仅排除协议关联的 thread/turn/item ID；匹配新轮次、来源受众、原请求者、所有者、有效期与群版本。事务式领取后才响应新 RPC；参数变化须重新确认，响应不明不会自动再次执行。
- 原生 user-input 无法证明只是普通澄清时仍交所有者；答复在新轮次作为该问题的材料，不转化为任意命令授权。缺少完整补丁的文件审批和截断快照安全取消，私聊明确说明不能自动恢复，只可关闭事项或由所有者核对后发新请求。

- 普通业务链接不再仅因 `state`、`ticket`、业务 `code` 或公开客户端标识被整行隐藏；真实认证地址、回调授权码、凭据、认证头和私钥仍受保护。所有者私聊确认的原始参数和私聊卡链接不投影到共享群卡。
- 共享群卡指导中的“账号必须匹配请求者”改为新模式匹配固定执行所有者；不再与身份注入冲突。新建群文档仍复用现有 CLI，要求新文档群只读并回读核验；既有私人资源不顺带分享，部分成功不得重复创建。
